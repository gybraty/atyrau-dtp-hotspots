# dtp-hotspots

[![CI](https://github.com/gybraty/atyrau-dtp-hotspots/actions/workflows/ci.yml/badge.svg)](https://github.com/gybraty/atyrau-dtp-hotspots/actions/workflows/ci.yml)
[![Deploy demo](https://github.com/gybraty/atyrau-dtp-hotspots/actions/workflows/deploy.yml/badge.svg)](https://github.com/gybraty/atyrau-dtp-hotspots/actions/workflows/deploy.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Spatial and temporal hotspot analysis of road traffic accidents (ДТП) for the
Atyrau region, Kazakhstan. Takes a CSV export of accident records, identifies
statistically significant accident clusters, and produces an interactive map,
charts, and machine-readable GeoJSON.

**Live demo** (built by CI from the synthetic sample):
<https://gybraty.github.io/atyrau-dtp-hotspots/>

## Scientific method

- **Kernel density estimation (KDE)** — `scipy.stats.gaussian_kde` over accident
  coordinates projected to local meters, producing a continuous density surface.
- **Getis-Ord Gi\*** (Getis & Ord, 1992) — accidents are binned into a square grid
  (250 m cells by default); each cell gets a z-score measuring whether it and its
  3×3 neighborhood contain significantly more accidents than expected under spatial
  randomness. Cells with z ≥ 1.96 (95% confidence) are reported as hotspots.
- **Temporal profiling** — accident counts by hour of day, weekday, and month;
  severity and casualty breakdowns.

## Installation

```bash
git clone https://github.com/gybraty/atyrau-dtp-hotspots.git
cd atyrau-dtp-hotspots
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
```

Requires Python ≥ 3.11.

## Usage

```bash
dtp-hotspots report data/sample.csv -o out
```

Options: `--cell 250` (grid cell size, meters), `--z 1.96` (Gi* significance threshold).

Outputs in `out/`:

| File | Contents |
|------|----------|
| `map.html` | Interactive map: accident heatmap + significant hotspot cells |
| `charts/*.png` | Accidents by hour, weekday, month, severity |
| `hotspots.geojson` | Hotspot cell polygons with count and z-score (ready for any GIS) |
| `summary.md` | Text summary: period, casualties, peaks, top-10 hotspots |

## Input data

CSV with columns `id,type,severity,lat,lng,datetime,dead,injured`.
`severity` ∈ {minor, major, fatal}; coordinates in WGS84.

Data is loaded **manually** — this repository contains no real accident records.
`data/sample.csv` is fully synthetic (generated by `scripts/make_sample.py`,
fixed seed). The real dataset comes from a police GIS PostgreSQL database;
export with:

```sql
\copy (SELECT a.id, t.name AS type, a.severity, a.lat, a.lng,
              a.datetime, a.dead, a.injured
       FROM "Accident" a JOIN "IncidentType" t ON t.id = a."typeId")
TO 'crashes.csv' CSV HEADER;
```

Rows failing validation (bad dates, coordinates outside the region bbox,
unknown severity, negative casualties) are dropped and counted in the report.

## Technology choices

| Choice | Why |
|--------|-----|
| **Python** | De-facto standard for scientific data processing; rich geospatial/stats ecosystem |
| **pandas + numpy** | Vectorized CSV processing and grid math; no hand-rolled loops |
| **scipy** | Reference implementations of `gaussian_kde` and convolution (used for Gi* neighborhood sums) |
| **folium** | Interactive Leaflet maps from Python with zero JavaScript; output is a self-contained HTML file, ideal for GitHub Pages |
| **matplotlib** | Publication-quality static charts for reports |
| **No geopandas/pyproj** | The grid-based Gi* only needs a local equirectangular projection (<0.1% error at city scale); avoiding heavy GEOS/PROJ binaries keeps install and CI fast |
| **pytest + ruff** | Minimal, standard test runner and linter |
| **GitHub Actions** | CI/CD co-located with the repository; no external infrastructure |

## CI/CD

- **CI** (`.github/workflows/ci.yml`): on every push and pull request — `ruff`
  lint + `pytest` on a Python 3.11/3.12 matrix.
- **CD** (`.github/workflows/deploy.yml`): on every push to `main` — runs the
  tool on the synthetic sample and deploys the resulting report to GitHub Pages.
  The live demo is therefore always built by the latest code.

## Tests

```bash
pip install -e ".[dev]"
pytest
```

Covers: CSV validation (each rejection reason), local projection round-trip,
Gi* flags a planted hot cell and stays flat on uniform data, the full grid
pipeline recovers a known synthetic cluster, temporal counts, and an
end-to-end CLI run checking every output artifact.

## Limitations

- Gi* on a sparse regional grid inflates significance around isolated points;
  intended use is city-scale data where cells are reasonably populated.
- Equirectangular projection is a city-scale approximation (see
  `analysis.py`); swap in pyproj/UTM 42N for region-wide precision work.
